你这部分确实要**根据代码重新画**，不能再按“token-level CrossViT attention matrix”那种理想结构画。你的代码里实际是：

**Time branch / Spec branch 编码后先做全局平均池化**，也就是：

```text
time tokens → mean pooling → time feature
spec tokens → mean pooling → spec feature
```

然后才进入 cross-attention。也就是说，cross-modal fusion 不是大规模 `N_time × N_spec` token 交叉注意力，而更准确地说是 **pooled feature-level bidirectional cross-modal attention / feature calibration**。代码里也能看到：`time_feat.mean(dim=1)` 和 `spec_feat.mean(dim=1)` 之后，再 `unsqueeze(1)` 变成长度为 1 的序列，然后做 `Time → Spectrogram` 和 `Spectrogram → Time` 两个方向的 Q/K/V attention，最后 residual + norm，再 concat 后送入 classifier。

所以从 **15. Cross-modal Attention Fusion** 开始，建议你这样画。

## 15. Cross-modal Attention Fusion 应该怎么画

### 你原来不该怎么画

不要画成这种：

```text
Time tokens  ×  Spectrogram tokens
      ↓
large attention matrix N_time × N_spec
```

因为这会暗示你的模型在 token 层面对时域 token 和谱图 token 做完整交叉注意力，但你的代码里实际是在 pooling 后融合。这样画会和代码不一致。

---

## 推荐画法：画成“池化特征级双向交叉校准”

这一块建议画成一个大框，标题仍然叫：

```text
C. Cross-modal Attention Fusion
```

内部画成三层结构。

---

### 第一层：输入是两个 pooled feature，不是两串长 token

左侧输入画：

```text
Time feature  F_t
[green vector blocks]
```

右侧或下侧输入画：

```text
Spectrogram feature  F_s
[gray vector blocks]
```

图形上不要画很多 token，只画一排短向量块即可，比如：

```text
F_t:  □ □ □ □ □
F_s:  ■ ■ ■ ■ ■
```

其中：

* `F_t` 用浅绿色；
* `F_s` 用浅灰色；
* 每个向量块可以画 5–6 个小矩形；
* 不要画成 129 个 time tokens 或 64 个 spec tokens。

### 为什么这么画

因为你的代码实际先把时域 encoder 输出和频域 encoder 输出做 `mean(dim=1)`，也就是全局平均池化，然后才进入 cross-attention。这个图形能准确表达：**fusion 发生在模态级特征上，而不是原始 token 级别上**。

---

## 15.1 Time → Spectrogram 分支怎么画

画一个小子框：

```text
Time → Spectrogram Attention
```

内部建议画成：

```text
F_t → Q_t
F_s → K_s, V_s
Q_t × K_s → α_t→s
α_t→s · V_s → calibrated time feature
```

但是总图里不要写这么长。图形可以简化为：

```text
F_t ── Q ┐
         ├─ Attention α_t→s ── Add & Norm ── F'_t
F_s ─K,V┘
```

draw.io 画法：

1. 左上放绿色向量 `F_t`；
2. 左下放灰色向量 `F_s`；
3. 从 `F_t` 拉箭头到一个小矩形 `Q`；
4. 从 `F_s` 拉两条箭头到 `K,V`；
5. `Q` 和 `K,V` 共同指向一个小方阵或小圆点，标 `α_t→s`；
6. 再指向 `Add & Norm`；
7. 输出 `F'_t`。

### 为什么这么画

这对应代码里的：

```text
q1 = q_proj[0](time_feat)
k2 = k_proj[0](spec_feat)
v2 = v_proj[0](spec_feat)
```

也就是 **时域特征作为 Query，谱图特征作为 Key/Value**。这不是简单拼接，而是“用谱图信息校准时域特征”。

---

## 15.2 Spectrogram → Time 分支怎么画

第二个子框画成对称结构：

```text
Spectrogram → Time Attention
```

图形：

```text
F_s ── Q ┐
         ├─ Attention α_s→t ── Add & Norm ── F'_s
F_t ─K,V┘
```

draw.io 画法和上一块完全对称，只是颜色和方向反过来：

* `F_s` 是 Query；
* `F_t` 是 Key/Value；
* 输出是 `F'_s`。

### 为什么这么画

代码里第二个方向是：

```text
q2 = q_proj[1](spec_feat)
k1 = k_proj[1](time_feat)
v1 = v_proj[1](time_feat)
```

所以这是 **谱图特征从时域特征中吸收补充信息**。这就比单向融合更像“互补模态校准”。

---

## 15.3 Attention 矩阵怎么画

这里一定要注意：**不要画大热力矩阵**。

你可以画一个很小的 attention block，比如：

```text
α_t→s
[ 1×1 / H heads ]
```

或者画成多个小圆点：

```text
head 1  head 2  ...  head H
```

更推荐画成：

```text
Multi-head attention weights
○ ○ ○ ○
```

旁边标：

```text
H heads
```

不要画：

```text
129 × 64 attention map
```

因为你的 cross-attention 输入序列长度是 1，对应的是 feature-level multi-head attention，不是 token-level attention map。

### 为什么这么画

你的 attention 可视化脚本里也是先 `unsqueeze(1)`，所以 attention 的 query/key sequence length 是 1。虽然有 multi-head，但每个 head 不是在很多 token 之间选择，而是对两个 pooled modality features 做交互。因此在总图中画“大矩阵”会误导读者。

---

## 15.4 Cross-modal Fusion 最终推荐版画法

我建议你这一块最终画成下面这个结构：

```text
                ┌──────────────────────────────┐
F_t ── Q_t ──┐  │ Time → Spectrogram Attention │ ── Add & Norm ── F'_t
F_s ─ K_s,V_s┘  └──────────────────────────────┘

F_s ── Q_s ──┐  ┌──────────────────────────────┐
F_t ─ K_t,V_t┘  │ Spectrogram → Time Attention │ ── Add & Norm ── F'_s
                └──────────────────────────────┘
```

然后两个输出汇合：

```text
F'_t + F'_s → Concatenation → F_fusion
```

在图里可以画成：

```text
F'_t  □ □ □ □
          \
           →  [Concat]  →  F_fusion
          /
F'_s  ■ ■ ■ ■
```

# 16. Fused feature (F_{\text{fusion}}) 怎么画

## 推荐画法

画成一排混合颜色的向量块：

```text
F_fusion:
□ ■ □ ■ □ ■
```

其中：

* 绿色块代表 time-domain contribution；
* 灰色块代表 spectrogram contribution；
* 混合排列代表 concat 后的融合特征。

或者更严格地画成：

```text
[F'_t] [F'_s]
```

也就是左半段绿色、右半段灰色：

```text
□□□□ | ■■■■
```

我更推荐第二种，因为你的代码里最后是：

```text
fused_feat = torch.cat([fused_time, fused_spec], dim=1)
```

所以它不是完全混合成一串随机交错 token，而是**时域校准特征和谱图校准特征的拼接**。

## 为什么这么画

这样读者能准确理解：

```text
F_fusion = Concat(F'_t, F'_s)
```

不是简单相加，也不是 attention map 输出的 token 序列。

# 20. Source-domain Pre-training 怎么画

这部分要和你的抗遗忘迁移逻辑对应，不只是普通训练。

你的 V3 代码里是先创建教师模型，加载源域模型参数，然后冻结教师模型；随后混合源域和目标域数据训练学生模型，并用知识蒸馏损失约束学生输出。 所以这部分建议画成：

```text

        ↓
Teacher model θ_s
        ↓
Distillation constraint
```

但如果你是在总图第三部分单独画 source pre-training，可以保持竖向三框：

```text
Train on source domain
↓
Learn stable discriminative fault knowledge
↓
Save as teacher / initialization
```

## 怎么图形化

### 第一框：Train on source domain

可以画：

```text
Source data → CrossViT
```

用一个小模型块表示即可，不要再画完整 CrossViT。

### 第二框：Stable discriminative knowledge

画一个小 feature space：

```text
○ ○ ○      △ △ △
○ ○ ○      △ △ △
```

中间画一条分类边界线。

这表示模型在源域学到了稳定故障判别边界。

### 第三框：Teacher / initialization

画一个小参数符号：

```text
θ_s
```

或者：

```text
Teacher model
```

旁边加一个锁形状不太建议，因为你之前不想图标化；可以用 `frozen` 小字或虚线框表示冻结。

## 为什么这么画

因为你的防遗忘逻辑不是“重新训练一个模型”，而是：

1. 源域预训练得到初始模型；
2. 保存成 teacher；
3. 目标域迁移时用 distillation / LWF 保留源域知识。

这与代码里冻结 teacher、混合源域和目标域样本、用蒸馏损失训练学生模型是一致的。

你这一块不要再画成“token-level CrossViT attention”。
