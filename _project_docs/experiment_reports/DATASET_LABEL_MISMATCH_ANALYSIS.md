# 数据集标签不匹配问题分析报告

## 执行摘要

通过对数据集2的深入分析，发现了一个**严重的标签不匹配问题**：

- **源域 (1.0kW)** 有 16 个故障代码类别
- **目标域 (3.0kW)** 有 15 个故障代码类别
- **只有 '0_00' (正常) 是两个域共有的类别**
- **所有其他故障代码都完全不同**

这引发了对实验结果有效性的严重质疑。

## 三、数据处理器的标签映射机制

### 3.1 标签映射代码

```python
fault_codes = sorted(df['fault_code'].unique())
n_classes = len(fault_codes)
fault_to_label = {code: i for i, code in enumerate(fault_codes)}
```

### 3.2 标签映射结果

**源域标签映射**：
- `'0_00' -> 0`
- `'0_68' -> 1`
- `'0_81' -> 2`
- ...
- `'7_56' -> 15`

**目标域标签映射**：
- `'0_00' -> 0`
- `'13_30' -> 1`
- `'17_86' -> 2`
- ...
- `'9_81' -> 14`

### 3.3 标签不匹配问题

**核心问题**：标签索引不对应相同的故障类型！

例如：
- 源域的标签 `1` 代表故障 `'0_68'`
- 目标域的标签 `1` 代表故障 `'13_30'`
- 这两个故障代码**不是同一个故障**！

这意味着：
1. 模型在源域学习时，标签 `1` 代表 `'0_68'` 的特征
2. 在目标域测试时，标签 `1` 代表 `'13_30'` 的特征
3. **模型无法正确识别目标域的故障**，因为它从未见过 `'13_30'` 这个故障

## 四、实验结果分析

### 4.1 EXP2 实验结果（无适应）

| 指标 | 结果 |
|------|------|
| 源域测试准确率 | 94.23% |
| 目标域测试准确率 | 4.49% |
| 性能下降 | 89.74% |

**分析**：
- 目标域准确率 4.49% 接近随机猜测水平 (1/16 ≈ 6.25%)
- 这是**符合预期的**，因为模型从未见过目标域的故障类型

### 4.2 EXP3 实验结果（有监督微调）

| 指标 | 结果 |
|------|------|
| 源域测试准确率 | 91.03% |
| 目标域测试准确率 | 89.10% |
| 平衡分 | 99.10 |

**分析**：
- 目标域准确率达到 89.10%，**非常高**
- 但这需要使用目标域的标签进行有监督微调
- **关键问题**：如果标签不匹配，微调后的模型输出是什么？

### 4.3 有监督微调的问题

从代码分析可以看到，EXP3 的微调阶段使用了：

```python
target_train_dataset = MultiModalFaultDataset(
    target_data['X_train_time'], target_data['X_train_spec'],
    target_data['y_train'],  # 使用目标域标签
    augment=False
)
```

这意味着：
1. 模型在目标域上进行**有监督训练**
2. 模型学习目标域的 15 个类别（标签 0-14）
3. 源域的 16 个类别知识被覆盖（灾难性遗忘）

**关键问题**：微调后的模型输出是什么？
- 如果输出是源域的 16 个类别，目标域准确率应该很低
- 如果输出是目标域的 15 个类别，源域准确率应该很低
- 但实验结果显示**两者都高**（91.03% 和 89.10%）

## 五、问题诊断

### 5.1 可能的解释

#### 解释 1：标签不匹配导致实验结果无效

如果标签确实不匹配：
- EXP3 的结果可能是**错误的**
- 模型可能只是在学习目标域的数据分布
- 源域和目标域的准确率计算可能有误

#### 解释 2：故障代码只是实验编号，代表相同故障类型

如果不同功率的故障代码代表相同的物理故障：
- 需要创建故障类型映射表
- 例如：`'0_68'` 和 `'13_30'` 可能都是"线圈故障5%严重度"
- 这需要查看原始数据采集文档确认

#### 解释 3：这是故意的 Zero-Shot 迁移学习设计

如果这是故意的 Zero-Shot 设计：
- 论文应该明确说明这一点
- 模型应该只能识别 `'0_00'` (Normal) 这个共同类别
- 但实验结果显示高准确率，与 Zero-Shot 设想矛盾

### 5.2 需要确认的问题

1. **故障代码的实际含义**
   - 不同功率的故障代码是否代表相同的物理故障？
   - 例如：`'0_68'` 和 `'13_30'` 是否是同一种故障？

2. **数据采集方案**
   - 需要查看原始数据采集文档
   - 确认故障代码的编号规则

3. **实验有效性**
   - 如果标签不匹配，实验结果是否有效？
   - 是否需要重新设计实验？

## 七、结论

### 7.1 核心发现

1. **标签不匹配问题确实存在**
   - 源域和目标域的故障代码几乎完全不同
   - 只有 `'0_00'` (Normal) 是共有的

2. **故障类型相同**
   - 两个域都有 `coil` 和 `interturn` 故障类型
   - 但故障代码编号不同

3. **实验结果需要重新评估**
   - EXP2 的结果符合预期（目标域准确率低）
   - EXP3 的结果需要解释（高准确率如何实现）

### 7.2 建议的下一步行动

1. **立即行动**
   - 查看原始数据采集文档，确认故障代码含义
   - 如果需要，创建故障类型映射表

2. **重新评估实验**
   - 根据故障代码的实际含义，重新评估实验结果
   - 如果是 Zero-Shot 设计，明确说明

3. **考虑修改实验设计**
   - 如果标签不匹配是问题，重新设计实验
   - 使用相同的故障类型标签
