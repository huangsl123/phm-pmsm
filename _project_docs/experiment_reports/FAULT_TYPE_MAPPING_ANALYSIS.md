## 三、关键发现

### 3.1 故障类型匹配

| 故障类型 | 源域 | 目标域 | 匹配 |
|---------|------|--------|------|
| **coil** | 57,157 样本 | 60,288 样本 | YES |
| **interturn** | 62,113 样本 | 63,918 样本 | YES |

**结论**: 源域和目标域有**完全相同的故障类型**！

### 3.2 故障代码命名模式

从故障代码的命名来看，可能是实验编号而不是故障类型：
- 源域: `0_68`, `0_81`, `12_17`, `21_69`, ...
- 目标域: `13_30`, `17_86`, `1_78`, `23_48`, ...

这些看起来更像是**实验条件编号**（可能代表不同的转速/负载组合），而不是故障类型本身。

### 3.3 `0_00` 的特殊性

`0_00` 在两个域中都存在，并且被标记为 `coil` 类型：
- 这可能表示**正常状态**下的线圈
- 样本数完全相同 (15,072)，表明这是相同的基准实验

## 四、对实验的影响

### 4.1 当前标签映射的问题

当前的数据处理器为每个故障代码分配独立的标签：
- 源域: 16 个标签 (0-15)
- 目标域: 15 个标签 (0-14)

这导致：
1. 源域的多个 `coil` 故障被分配不同的标签
2. 目标域的多个 `coil` 故障也被分配不同的标签
3. **相同故障类型在不同功率下无法对应**

### 4.2 正确的做法

应该创建基于**故障类型**的标签映射：

```python
# 正确的标签映射方式
fault_type_to_label = {
    'coil': 0,      # 线圈故障
    'interturn': 1, # 匝间故障
    'unknown': 2    # 未知类型
}

# 然后所有功率的数据都使用相同的标签空间
```

这样：
1. 源域和目标域共享相同的标签空间
2. 模型学习的是故障类型而不是实验编号
3. 跨域迁移学习变得有意义

## 六、结论

### 6.1 关键发现

1. **故障类型是对应的**
   - 源域和目标域有相同的故障类型 (coil, interturn)
   - 故障代码只是实验编号，不代表故障类型

2. **当前标签映射存在问题**
   - 使用故障代码作为标签导致标签空间不匹配
   - 应该使用故障类型作为标签
